# Opt's own MCP servers, and a folder of its own

Opt's MCP servers are now a list of its own, `<dir>/mcp.json`, apart from
the user's Claude Code. A server added to Claude Code no longer reaches
Opt, and one added for Opt stays out of Claude Code. Opt's tools also run in
a folder of their own by default, `opt-chat` in the system's temp folder,
instead of the home folder.

- Every call with the user's setup (turns, side questions, subagents and the
  page's own call) loads Opt's file after the chat's own tools:
  `--mcp-config <chat's> <dir>/mcp.json`. Claude Code takes several files
  in one flag. The file is read as each call starts, so an edit, by hand or
  by Opt, needs no reload.
- The same calls keep out Claude Code's own servers in their settings,
  `deniedMcpServers` (`ccDenied`): the user's (`mcpServers` in
  `~/.claude.json`), those Claude Code keeps for the folder the call runs
  in and each folder above it (`projects`, by the path and by its real
  path, `/var` being `/private/var` on macOS), and those of a `.mcp.json`
  in any of them. A name Opt's file also has is left out of the list: a
  server from `--mcp-config` replaces Claude Code's of the same name, which
  then shows once, as Opt's. Opt's own `opt` server is never denied.
- Compactions are unchanged: bare, with `--strict-mcp-config`.
- The prompt names the file, in a paragraph that is there only with it
  (`mcpPrompt`), so the user can ask Opt to add a server.

## Why not --strict-mcp-config

`--strict-mcp-config` loads only the files given, but it also drops the
claude.ai connectors and the plugins' servers, even with
`ENABLE_CLAUDEAI_MCP_SERVERS` set, and neither can be copied into a file.
Denying Claude Code's servers by name keeps those two and drops only the
servers a file can hold.

## The first copy

At start, with `-claude-config` on and no `mcp.json` (`seedOptMCP`), opt-chat
copies the servers Claude Code gave the folder Opt worked in until then: the
home folder, or `-cwd` when set. That is the user's servers and the
folder's own, the folder's winning on a name, as in Claude Code. The
configs are copied as they are, keys included, so the file is written
0600. The folder's `disabledMcpServers` go on Opt's list of servers off
(`mcpOff` in `settings.json`) unless that list or the one for subagents has
them already, so a server off in Claude Code doesn't come on in Opt. The
settings are written before the file: with the file there, the copy never
runs again. Claude Code's config is only read.

A file that isn't JSON is left out of the calls, with a warning, rather
than passed on: one bad edit would otherwise stop every call. A server
entry that Claude Code can't use (valid JSON, wrong fields) doesn't stop a
call; Claude Code leaves that server out.

## The folder

`-cwd` unset is now `$TMPDIR/opt-chat` (`os.TempDir()`), not the home
folder. `$TMPDIR` on macOS is a folder only the user can write to, under
`/var/folders`. `/tmp` was not used: any program can write there, and a
`CLAUDE.md` or `.claude/settings.json` dropped in `/tmp` would be loaded by
Opt's calls. macOS deletes files in `$TMPDIR` unused for 3 days, so each
call makes the folder again (0700) before it starts.

Nothing saved depends on the folder. Claude Code keeps a session under
`~/.claude/projects/<folder>/`, and `--resume` finds it from another
folder; opt-chat looks for a subagent's session in every project folder
(`sessionPath`). The `@` completion still starts from the home folder, or
from `-cwd` when set.

What the home folder gave that the new folder doesn't: Claude Code read
`~/.claude/settings.local.json` as that folder's local settings, and its
`projects` entry for the home folder (servers and servers kept off), which
the copy above carries over.
